# Brief: user-profile

## Problem
栄養管理を行うには、身長・体重などの身体情報や活動レベル・既往症・食の嗜好といった生活習慣情報が必要になる。これらを毎回入力するのは手間であり、また体重・体脂肪率の推移が記録されないと、ダイエットの進捗や健康状態の変化を把握できない。

## Current State
プロジェクトは新規（greenfield）であり、入力・保存・記録の仕組みは何も存在しない。

## Desired Outcome
ユーザーが身体情報・生活習慣情報を一度入力・保存すれば、以降は再入力なしで栄養計算・献立生成に利用できる状態。また、体重・体脂肪率を日次で記録でき、その推移をグラフで確認できる状態。

## Approach
シングルユーザー想定（認証機能なし）のプロフィールデータストアを構築する。必須項目（身長・体重・年齢・性別）と拡張項目（体脂肪率、既往症・アレルギー・服薬情報、妊娠/授乳有無、睡眠時間、運動習慣、食の嗜好・NG食材、飲酒喫煙習慣、調理時間/スキル、予算感）を保存する。ダイエットモード用に目標体重・目標達成期間に加え、食事制限設定（タイプ・強度・自由記述）も保持する。体重・体脂肪率・摂取カロリー実績・追加運動記録は日次ログとして時系列に保存し、推移グラフやカロリー収支表示のためのデータを提供する。

活動レベルは単一の選択肢としてユーザーに直接選ばせるのではなく、運動習慣の詳細情報から算出する。運動習慣は「お仕事中の活動度」（主に座って過ごす/座り・立ち半々/主に立つ・体を動かす仕事）、「通勤手段」（徒歩・自転車が中心/電車・バスなど/車・ほぼ歩かない）、任意の「1日の平均歩数」に加え、1週間の運動量を場面（通勤/仕事中/帰宅後/休日/その他）ごとに複数行で記録できる表形式のデータ（場面・内容・頻度・1回の時間・強度）として保持する。この運動習慣データはnutrition-engineに渡され、TDEE計算用の活動係数の算出に使われる。

食事制限設定はタイプ（制限なし/糖質制限/脂質制限/高たんぱく/カロリー制限のみ）と強度（ゆるやか/標準/しっかり）を組み合わせて選択できるようにし、加えて「その他食事制限」として自由記述欄（例:「16時以降の糖質を控えたい」等）を設け、menu-generationでの献立生成時の参考情報として渡せるようにする。

摂取カロリー実績は、menu-generationが算出する計画献立のkcalをデフォルト値として自動反映し、実際に食べた内容が異なる場合はユーザーが手動で上書きできるハイブリッド方式とする。追加運動記録（種目・時間・想定消費カロリー）は日次ログの一部として保存し、nutrition-engineがTDEEに加算する消費カロリー計算に利用する。

## Scope
- **In**:
  - プロフィール項目（必須・拡張項目）の入力フォームと保存
  - 食事制限設定（タイプ・強度の選択、その他食事制限の自由記述）の入力と保存
  - プロフィールの更新・再編集
  - 体重・体脂肪率の日次記録（ログ）機能
  - 摂取カロリー実績の日次記録（計画値の自動反映＋手動上書き）
  - 追加運動記録（種目・時間・想定消費カロリー）の日次記録
  - 体重・体脂肪率・摂取カロリー実績・運動記録の推移データ提供（グラフ描画は results-dashboard 側の責務）
- **Out**:
  - マルチユーザー・認証機能（将来拡張）
  - 栄養目標値の計算（nutrition-engine の責務）
  - 献立生成（menu-generation の責務）
  - グラフ描画・結果画面のUI（results-dashboard の責務）

## Boundary Candidates
- プロフィール（身体情報・生活習慣情報・食事制限設定）の入力/保存/更新
- 体重・体脂肪率・摂取カロリー実績・運動記録の日次ログ記録

## Out of Boundary
- 栄養計算ロジック（BMR/TDEE/PFC等）は持たない
- 献立生成ロジックは持たない
- 結果画面の可視化・レイアウトは持たない

## Upstream / Downstream
- **Upstream**: なし（プロジェクトの起点となるspec）
- **Downstream**: nutrition-engine（プロフィールデータ・運動習慣（お仕事中の活動度・通勤手段・1週間の運動量）・食事制限設定・追加運動記録を入力として、活動レベル（活動係数）・栄養目標値・消費カロリーを算出）、menu-generation（食の嗜好・NG食材・食事制限設定を献立生成の入力として利用）、results-dashboard（体重・カロリー実績ログの推移データを表示）

## Existing Spec Touchpoints
- **Extends**: なし（新規spec）
- **Adjacent**: nutrition-engine, menu-generation, results-dashboard がこのspecの保存データを参照する

## Constraints
- シングルユーザー想定のため認証・認可の実装は不要
- 技術スタック（言語・フレームワーク・DB）は design フェーズで決定
